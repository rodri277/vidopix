# ADR 018: Third-party notices generated from the build

- Status: Accepted
- Phase: after 5

## Context

The app redistributes open source code (React, Zod, Workbox and others, under MIT and ISC) and two fonts under the SIL Open Font License. These licenses require their text to travel with the copies, and the OFL says so explicitly for the fonts. A list written by hand from `package.json` would be wrong in both directions: dev dependencies are not shipped, while the service worker carries Workbox and a second copy of `idb` that no `package.json` of this project names.

## Decision

- `THIRD_PARTY_LICENSES.md` is generated by `tools/third-party-licenses.mjs` from the production build, not from the dependency list. The source maps name every package whose code is in a bundle, with the exact installed version; each font file is traced back to the dependency that ships a file of the same name; the two modules written by plugins at build time (`virtual:pwa-register` and `sw.js`) are attributed to `vite-plugin-pwa` and `workbox-build`.
- Each section copies the license file found inside the package, untouched. A package without a license file, a source that cannot be placed, or a file in the build that is neither the project's own nor traceable fails the run.
- `pnpm build` ends with `--check`, so the build (in CI and on Vercel) fails when the file no longer matches what is shipped. `pnpm licenses` rewrites it.
- The build publishes the file as `/third-party-licenses.txt` and the privacy note as `/privacy.txt`. They are not precached; they are not needed to draw offline.
- The file opens with a notice that the project is not affiliated with the palette authors, Lospec, or the authors of the packages. A test checks that every preset palette author is named there.

## Alternatives considered

- **A license plugin for the bundler.** It runs inside one Rollup build, so it would not see the Workbox runtime that `workbox-build` bundles on its own for the service worker, and it adds a dependency.
- **`pnpm licenses list --prod`.** Lists what is installed for production, not what is bundled: it misses Workbox and the second `idb`, and would keep listing a dependency the bundle no longer uses.

## Consequences

- Adding, removing or upgrading a shipped dependency fails the build until `pnpm licenses` is run and the result committed. This is the point: the notices cannot drift.
- Production source maps are now load-bearing; turning them off would break the check, and it would say so.
